Telinfy Platforms

Telinfy WhatsApp business account is a unique identifier inside the platform to do operations on registered WhatsApp business accounts. All the WhatsApp operations inside the Telinfy platform are based on this business account. The App ID, App Name, API Key, Access Token and webhook registration will be shared by the Telinfy support team as part of the onboarding process.

Important parameters

API Key

Each Telinfy account is assigned a unique API key. To access your API key, log in to your Telinfy account using your username and password. Navigate to the My Account section, where you'll find your API key listed under the API Key section.

Template Name

– A template name in WhatsApp refers to the unique identifier assigned to a message template that businesses use to send pre-approved, structured messages. These templates are typically used for notifications, updates, or transactional messages sent to users who have opted in to receive communication

Template languages

Template languages in WhatsApp refer to the specific languages in which a message template can be created and sent. WhatsApp supports multi-language templates to enable businesses to communicate with users in their preferred language, ensuring better engagement and understanding.

Media & Interactive

Multimedia such as Image, Video & PDF Should be passed as link with their corresponding extensions.

The Supported Formats for Media Upload while adding templates are:

Image: PNG & JPG

Video: MP4

Document: PDF

Template API Messaging

Template messages are the set of messages which the entity sends to its customer. Every new message sent from the entity to customer should be approved by WhatsApp. Template approval can be taken from Telinfy platforms. Once approved these templates can be used for campaign and API integration with various applications.

Conversation APIs

You can participate in a direct conversation / chat with a customer only if you are in a Customer Service Window. Which means the customer should be replied to your template message within the last 24 hours. If the customer’s last message is 24 hours before and if you try to send a normal message to the customer, it won’t be successful. If you need to resume a conversation with that customer, you must send a template message to the customer, and he/she should reply to you. Direct messaging supports the following message types: Text message, media messages, contacts and location messages and interactive messages.

Partner Webhook

Introduction

Webhooks are a mechanism which enables applications to communicate with each other programmatically. It allows you to send real-time data from one application to another whenever a given event occurs. You can use the webhook to determine which endpoint we should forward the real-time data.

Whenever a specific event occurs, the WhatsApp Business API Client sees the event, collects the data, and immediately sends a notification (user-defined HTTP callbacks) to the webhook URL specified.

  1. messages: Used to notify you when you get a new message and what is in the new message.
  2. statuses: Used to notify you when there's a status change in a message you sent.
  3. errors: When there are any out-of-band errors that occur in the normal operation of the application, this array provides a description of the error.

To deploy a live partner-webhook that can receive events from the WhatsApp Business API client, your code must have HTTPS support and a valid SSL certificate.

Webhook URL

The webhook URL is a resource address to which the WhatsApp Servers sends notifications, which are triggered by specific events. A suitable webhook URL must be supplied by you or by your Partner Software Provider / ISV. You only need to set your Webhook URL once. Although you can update it or remove it at any time.

You must set a Webhook URL once per number.

Webhook Components

Webhooks have a top-level array field indicating what is being communicated. The members of the array are JSON objects with detailed fields relevant to the Webhook.

WhatsApp Business API webhooks can contain the following objects:

Name

Object contents

whatsappBusinessId

Your business account unique key

messages

Webhook notifications of received messages are contained within a messages object.

statuses

The statuses object keeps you apprised of the status of messages between you and users or groups.

errors

When there are any out-of-band errors that occur in the normal operation of the application, the errors array provides a description of the error. This type of error can be caused by transient network connectivity errors, invalid credentials, management controllers in unavailable status, etc.

The messages Object

Name

Description

contacts type: Array of contact profile information

Provides all the information about the contact —see contacts object. This object only applies to text, contacts, and location messages. It is not currently supported for media messages and is not applicable for system messages. Inside contacts, the profile object is nested.

messages type: Array of any type of message objects

Provides all of the information about the incoming message —see messages object. Inside messages, the following objects are nested: context, identity, media, referral, text, location, contacts, system, and interactive.

WhatsApp defines a conversation as a 24-hour session of messaging between a person and a business. There is no limit on the number of messages that can be changed in the 24-hour window. The 24-hour conversation session begins when: A business-initiated message is delivered to a user A business’ reply to a user message is delivered the 24-hour conversation session is different from the 24-hour customer support window. The customer support window is a rolling window that is refreshed when a user-initiated message is delivered to a business. Within the customer support window businesses can send free-form messages. Any business- initiated message sent more than 24 hours after the last customer message must be a template message.

Status Updates

For each message your business sends, you will receive a notification about the status of the message. In the table below, click the arrow in the left column for the WhatsApp app equivalent to each status, if available.

Name

Description

deleted

A message send by the user was deleted by the user. Upon receiving this notification, you should ensure that the message is deleted from your system if it was downloaded from the server.

delivered

A message sent by your business was delivered to the user's device.

failed

A message sent by your business failed to send. A reason for the failure will be included in the callback. Check the error message documentation for help debugging: On-Premises API Errors Cloud API Error Codes and Troubleshooting Cloud API Error Codes and Troubleshooting

read

A message sent by your business was read by the user. read notifications are only available for users that have read receipts enabled. For users that do not have it enabled; you only receive the delivered notification.

sent

A message sent by your business is in transit within our systems. For On-Premises API users: To receive notifications for sent messages, set the sent_status setting to true in the application settings. The sent status notification is disabled by default.

warning

A message your business sent contains an item in a catalog that is not available or does not exist. For a status to be read, it must have been delivered. In some scenarios, such as when a user is in the chat screen and a message arrives, the message is delivered and read almost simultaneously. In this or other similar scenarios, the delivered notification will not be sent back, as it is believed that a message has been delivered if it has been read. The reason for this behavior is internal optimization.

The order of these notifications in your app may not reflect the actual timing of the message status. View the timestamp to determine the timing, if necessary.
